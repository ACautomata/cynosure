## 1. 推算公式与出处（可复核性）

> 本节【上游】指 NVIDIA 真上游（NV-Generate-CTMR）；机制级 fork 与其逐字节零差异
> （`da438fe` 对拍，见 CONTEXT.md「上游锚」词条），本普查涉及的 resize 与
> `dynamic_infer` 均属机制级，两锚无分歧。

**resize 公式**（语义转录，零依赖，永不 import 上游代码）：

```python
# 【上游】scripts/diff_model_create_training_data.py:77-89 逐字语义
def round_number(number: int, base_number: int = 128) -> int:
    return int(max(round(float(number) / float(base_number)), 1.0) * float(base_number))
# resize 后影像网格 = 逐轴 round_number(轴长)；体素数 = 三轴乘积
```

- resize 目标 `dim` 逐轴独立计算（【上游】`:63` `Resized(spatial_size=dim)`；`:246-249`
  dim 取自 **RAS 之后**的 `meta["dim"]` 逐轴 `round_number`）。
- `round` 是 Python **half-to-even**：192/128=1.5→**256**，320/128=2.5→**256**（写成
  四舍五入会把 320 轴错成 384，差一整档）。`a/128` 中 128=2⁷，float 除法对任意
  a < 2⁵³ 精确，.5 边界恰落在 a ≡ 64 (mod 128)，无浮点噪声。
- **轴序不变性**：`Orientationd(axcodes="RAS")` 只置换/翻转（research/mrrate-data-spec.md
  §3.1），轴长**多重集**与朝向无关，故三轴乘积与 canonical 网格（本报告用三轴降序）
  可从元数据 `array_shape` 直接算出，与实际 RAS 后顺序无关。
- 六步链前五步（Load/ChannelFirst/Orientation/dtype/intensity）不改变空间网格，
  第 6 步 Resized 是唯一网格变换 → **零下载推算 = 实际 resize 后网格，精确无近似**。

**阈值定义**：encode 豁免判定 = 单样本（影像单通道）体素数 **≤** `320×320×160 =
16,384,000` 走整前向，严格 > 才滑窗（【上游】`utils.py:787-817` `dynamic_infer`，
roi_size=[320,320,160]）。本普查的「>16.38M 卷」= resize 后体素数 > 16,384,000，
即现网 `MaisiLatentEncoder` 显式拒绝、#139 encode 滑窗分支将要接管的卷。

**自检锁定**：脚本内置断言先行（任一不符立即中止）：half-to-even 四个 .5 边界
（192/320/448/576）、clamp（35→128）、普通档（128/384/560）、阈值两侧已知网格
（256³=16,777,216 超界；384×256×128=12,582,912 豁免）、真实样例行
（batch01 首行 `[560,560,35]`→512×512×128）。

## 3. 主结果

### 3.1 超界构成（全语料 61.43%，无 split 例外）

超界主力（按卷数降序的前 9 桶，`grid_buckets.csv` 为 38 桶全表）：

| resize 后网格 | image 体素 | latent 网格 | 卷数 | 占比 | 超界 |
|---|---|---|---|---|---|
| 256×256×128 | 8,388,608 | 64×64×32 | 267,664 | 37.95% | 否 |
| 512×512×128 | 33,554,432 | 128×128×32 | 194,085 | 27.52% | **是** |
| 384×384×128 | 18,874,368 | 96×96×32 | 67,196 | 9.53% | **是** |
| 256×256×256 | 16,777,216 | 64×64×64 | 40,889 | 5.80% | **是**（恰超 2.4%） |
| 512×384×128 | 25,165,824 | 128×96×32 | 23,337 | 3.31% | **是** |
| 512×512×256 | 67,108,864 | 128×128×64 | 22,890 | 3.25% | **是** |
| 384×384×256 | 37,748,736 | 96×96×64 | 15,836 | 2.25% | **是** |
| 384×384×384 | 56,623,104 | 96×96×96 | 12,370 | 1.75% | **是** |
| 1024×1024×128 | 134,217,728 | 256×256×32 | 12,108 | 1.72% | **是** |
| 其余 29 桶（38 桶总计） | | | 48,879 | 6.93% | 3 否（4,335）/ 26 是（44,544） |

超界形态学：主力超界是**细间距轴位**（in-plane 512 × 薄层 128，27.5%）与
**大 FOV 三平面**（384 档、256³），即 spec §4.1 预判的「大 FOV / 细体素卷落进更大
网格」的全语料定量版。modality×plane 每格都有超界（9.3%–94.5%）：最高 MRA
SAGITTAL 94.5%、FLAIR OBLIQUE 82.4%、FLAIR SAGITTAL 82.3%、T2w AXIAL 74.9%；
最低 MRA AXIAL 9.3%（细间距但 FOV 小）——见 `over_by_modality_plane.csv`。

### 3.2 上游语义旁证

#139 Problem Statement 已现场核验：上游生产链 665,371 训练 embeddings 正是经
`dynamic_infer` 分派——按本次普查的构成比例，其中 ~61% 量级的卷（>16.38M）走的
就是 `SlidingWindowInferer` 滑窗路径。上游 v1 语料的**主干编码路径是滑窗**，不是
长尾特例；这与「fork 机制文件与 NVIDIA 逐字节零差异」（CONTEXT.md「上游锚」词条，
机制级两锚无分歧）的锚定事实一致。

## 4. 对 #139 落地优先级的两读法

**读法 A：长尾占比高（实际情形，61.4%）→ encode 滑窗是硬前置，非优化项。**
- 不交付滑窗分支，MR-RATE 线 prepare 只能覆盖 38.6% 语料，且残缺是**结构性的**
  （细间距/大 FOV 卷系统性丢失，Real sample pool 的网格分布与上游 v1 语料错位 61 个点），
  不是随机减采样。Real sample pool、held-out real、判别器分布卫生全部受累。
- 探针（P1→P2→P3）是推翻 T12 的 gate，**必须最先做**——它通过与否决定滑窗分支
  合法性；探针通过后 encode 滑窗分支应排在 MR-RATE prepare/训练各票之前。
- decode 阈值修正（#139 decode 侧）与本普查联动：61.4% 超界卷的 latent 体素必然
  > 256,000 > 110,592（decode 滑窗阈值），encode 走滑窗的卷 decode 也必走滑窗——
  两侧行为在超界卷上天然一致；decode 修正的独立价值面在豁免侧 271,470 卷
  （38.49%，latent ∈ (110,592, 256,000] 的中等体），修正后与上游同豁免边界。
- **裁剪 fallback 覆盖面定量**：滑窗无硬尺寸上限，经验边界取「【上游】
  `docs/performance.md`
  实测过的最大训练网格 512×512×768 = 50,331,648」（spec §4.1 两表）。超出它的卷
  **79,170（11.23%）**——主力为 512×512×256（22,890）、768×768×128（18,359）、
  1024×1024×128（12,108）、384×384×384（12,370）、640×640×128（7,980）。若探针
  证伪滑窗或工程上放弃超界滑窗，裁剪/自研拼合方向要面对的就是这 11%，而非 61%；
  反之探针通过则 fallback 维持文档语义、不实现（#139 Out of Scope 维持），
  11% 只作为显存/时长风险的标注（该 11% 网格档上游未实测过，DCU 显存行为未知）。

**读法 B：长尾占比低（<5%，假设情形，实际未发生）→ 优先级反转。**
- encode 滑窗降级为长尾优化：显式拒绝 + 裁剪兜底即可保持语料 ≥95%，#139 的
  decode 阈值修正（影响所有中等体 latent 的可比性）与 prepare/训练在途票应排在
  encode 滑窗之前；探针仍做（改判 gate），但滑窗分支工程排期后置。
- 本普查证明现实是读法 A：两读法的分界判据（占比阈值 5% 只是示意刻度）由数据
  直接落在 A 侧，且超出一个量级。

## 5. 副产品：体素总和修正 spec §5.2 存储估算

全语料 resize 后 image 体素总和 **18,615,705,272,320**（18.6×10¹²），latent 体素总和
**290,870,394,880**。fp16（4 通道 × 2 B）latent 存储 ≈ **2.33 TB**（10¹² 口径），
比 spec §5.2 基于「256×256×128 为主」假设的 fp16 ≈ 1.4 TB 高 ~66%——该假设被本次
普查证伪（256×256×128 只占 38%）。算力估算同向放大：若按 1 s/卷（A100、256³ 档）
折算 705k 卷已不成立，超界卷需按滑窗时长重估（【上游】`docs/performance.md`：512×512×128
6–8 s、512×512×512 29–32 s 量级）。

## 6. 局限性

- 推算等价性依赖两条已论证事实（RAS 置换不变性 + 前五步不改网格），以及一条
  经验性假设：`array_shape` 忠实反映 NIfTI 头（30/30 抽查 + T6 旁证支持）。
- 「上游实测边界 50,331,648」是经验安全边界标记，不是 MONAI 滑窗的硬上限；
  11.23% 的归属随边界取值而变，报告按此口径写明。
- 官方 v1 训练清单未公开（spec §6），「与上游语料逐卷相等」不可主张；本普查口径
  统一用本 release 元数据（与 #78 裁决一致）。
